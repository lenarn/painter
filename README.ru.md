# Painter

Шаблон сайта-визитки художника: галерея с категориями, новости, «Об авторе»,
выставки, контакты. Сайт полностью статический — серверная часть не нужна,
результат работает на любом хостинге, включая дешёвый shared.

**Живой пример, собранный из этого кода:** https://eromanova.ru

[English version](README.md)

## Стек

- **Astro 5** — статическая генерация (SSG), без JS-фреймворков на клиенте
- **Go** (только стандартная библиотека) — инструменты: импортёр картин
  в каталог и локальная админка
- **Контент** — обычные JSON-файлы, без базы данных
- **Изображения** — WebP-варианты и `srcset` генерируются при сборке

## Возможности

- Галерея: категории, серии (блоки «Смотрите также» на странице работы),
  пометка «В наличии», ручной порядок внутри категории
- Страница работы: лайтбокс с листанием вперёд/назад внутри раздела,
  WebP/srcset
- Новости с пагинацией
- SEO: Open Graph, sitemap, JSON-LD, alt-тексты
- Доступность: Lighthouse 100 (a11y)
- Шрифты самохостятся, внешних CDN нет — сайт никуда не «звонит»

## Структура репозитория

```
web/                    сайт (Astro)
  src/pages/            страницы и маршруты
  src/components/       компоненты
  src/layouts/          базовый layout
  src/lib/              вспомогательные функции
  src/content/          контент в JSON: каталог картин, новости,
                        об авторе, образование, выставки, контакты
                        (твои данные, в репозиторий не входят)
  src/content/template/ заглушки контента — скопируй и заполни своими
                        данными
  src/assets/artworks/  оригиналы сканов картин (в репозиторий не входят)
  public/               статика: фавиконки, robots.txt
tools/
  catalogimport/        импортёр картин: sha256-дедуп, генерация catalog.json
  admin/                локальная админка: формы контента, проверка
                        орфографии, сборка, архив, превью
scripts/                PowerShell: запуск админки, сборка архива
.claude/skills/painter/ скилл Claude Code: операционный справочник по
                        репозиторию (структура, запуск, проверки, публикация)
```

## Требования

- Node.js 20+ и npm — для самого сайта
- Go 1.14+ — для импортёра и админки (сайт собирается и без Go)
- Windows 10/11 — для PowerShell-скриптов и админки; сайт (dev/build) работает
  на любой платформе

## Свой сайт по шагам

### 1. Клонировать и установить

```
git clone https://github.com/lenarn/painter.git
cd painter/web
npm install
```

### 2. Подготовить сканы картин

Создай по папке на категорию галереи — имя папки станет названием категории
на сайте. Вложенная папка даёт составную категорию (`живопись/масло`).
Один и тот же скан в нескольких папках = одна работа с несколькими
категориями; дубликаты определяются по хешу файла и не создают лишних записей.

### 3. Импортировать картины

Из корня репозитория (пути вывода — дефолтные):

```
go run ./tools/catalogimport "пейзажи" "портреты"
```

Перечисли свои папки. Инструмент:

- копирует уникальные файлы в `web/src/assets/artworks` с именами по хешу
  содержимого;
- пересоздаёт `web/src/content/catalog.json` — новые работы получают скелеты
  записей с `needs_metadata: true`;
- сохраняет `.bak`-бэкап предыдущего каталога и переносит метаданные уже
  известных работ (ключ — хеш), поэтому повторный запуск безопасен.

Каталог пересоздаётся из твоих папок, поэтому всё, что было в `catalog.json`
до запуска (включая записи шаблона), за один прогон заменяется на твои работы.

### 4. Скопировать заглушки контента

Контентные файлы (новости, «Об авторе», образование, выставки, контакты)
в репозиторий не входят — в них личные данные владельца сайта. Скопируй
заглушки из `web/src/content/template/` в `web/src/content/` и заполни
своим текстом:

```
copy web\src\content\template\news.json web\src\content\
copy web\src\content\template\about.json web\src\content\
copy web\src\content\template\education.json web\src\content\
copy web\src\content\template\exhibitions.json web\src\content\
copy web\src\content\template\contacts.json web\src\content\
```

(`catalog.example.json` остаётся на месте — это просто образец схемы;
сам `catalog.json` генерирует импортёр из шага 3.)

Ещё два личных места, которые ждёт код:

- положи свой портрет в `web/src/assets/about/photo1.jpg` (его импортирует
  страница «Об авторе»; путь легко поменять в `src/pages/about.astro`)
- укажи свой домен в `web/astro.config.mjs` (`site:`) — от него зависят
  canonical-ссылки, og:url и sitemap

### 5. Запустить dev-сервер

```
cd web
npm run dev
```

Открой http://localhost:4321 — галерея покажет твои категории и работы
под сгенерированными именами вида `artwork-a1b2c3d4e5`.

### 6. Заполнить метаданные работ

Для каждой записи `web/src/content/catalog.json` (вручную или через админку):

| Поле | Что это |
|---|---|
| `title`, `year`, `technique` | показываются на странице работы |
| `dimensions` | реальный размер, например `{ "w": 54, "h": 70, "unit": "см" }` |
| `caption` | подпись под работой |
| `alt` | alt-текст изображения |
| `featured` | показать на главной |
| `available` | пометка «В наличии» (работа в продаже) |
| `sort` | ручная позиция внутри категории, по имени категории |
| `related` | список slug'ов других работ — собирает серию «Смотрите также» |

### 7. Собрать и развернуть

```
cd web
npm run build
```

Результат — в `web/dist/`. Скопируй его содержимое в корень сайта на
хостинге — сайт статический, больше ничего не требуется.

## Админка (опционально, Windows)

Админка — небольшое локальное веб-приложение (Go, только стандартная
библиотека) для повседневной работы с контентом: JSON можно не править руками.

Запуск (скрипт сам соберёт админку из Go-исходников и откроет
http://localhost:8150 в браузере; остановка — Ctrl+C в её окне):

```
powershell -ExecutionPolicy Bypass -File scripts\start-admin.ps1
```

Строго локально — из самой админки ничего никуда не публикуется.

Что она умеет:

- **Править контент через формы**: каталог картин (названия, техника,
  размеры, подписи, порядок, связанные работы), новости, страницы «Об
  авторе», «Образование», «Выставки», «Контакты»
- **Проверять орфографию** черновиков (Яндекс Спеллер)
- **Запускать сайт**: собрать его и поднять превью на http://localhost:4321
  (если порт занят, то, что там работает, сначала гасится)
- **Готовить публикацию**: собрать сайт и упаковать
  `publish/site-<дата>.zip` с отчётом изменений против прошлого архива —
  сколько файлов добавлено, изменено или удалено и нужно ли чистить корень
  хостинга перед распаковкой

## Деплой архивом

`scripts\publish-pack.ps1` собирает сайт и упаковывает
`publish/site-<дата>.zip` (содержимое dist в корне архива) плюс текстовый
манифест. Распакуй в корень сайта на хостинге (например, в `public_html`
на shared-хостинге).

## Изображения и репозиторий

`web/src/assets/artworks/` в `.gitignore` — свои файлы картинок в git
не попадают; убери строку, если хочешь хранить их в репозитории. Контентные
JSON в `web/src/content/` игнорируются по той же причине: в них личные данные
владельца сайта. Поэтому свежий клон показывает пустой сайт, пока не запущен
импорт со своими папками (шаг 3) и не скопированы заглушки контента (шаг 4).
